> 표시: ✅ 확인됨 · 📏 실측으로 맞춤 · ❓ 미확인 ([README](README.md) 참고)

다이나웨어(Dynaware)의 PC-9801용 시퀀서 **Ballade**와, Roland의 ミュージくん /
ミュージ郎 패키지에 들어 있던 같은 엔진의 곡 파일이다. Recomposer와 확장자가
같지만 **전혀 다른 포맷**이라 파일 첫 줄로 구분한다.

결과: 17곡 중 **15곡이 SNG2S와 음표까지 일치.** 나머지 2곡은 파일 쪽 문제다(5절).

## 1. 파일 첫 줄

```
"BALLADE SONG Ver. n.nn \r\n" <제목> "\r\n\x1a"      (Shift-JIS)
```

| 버전 | 프로그램 | 파트 수 |
|---|---|---|
| `Ver. 1.00` | Ballade / ミュージくん | 10 |
| `Ver. 2.00` | Ballade2 / ミュージ郎 | 10 |
| `Ver. 3.00` | ミュージ郎2 | 10 |
| `Ver. 4.00` | Ballade3 | 16 |

버전 표시는 이 줄이 유일하다. 모든 수는 **리틀 엔디언**이다(x86 프로그램).

## 2. 전체 구조 — 메모리를 그대로 저장한 파일

```
0x46        블록 크기표: (파트 수 + 1) × u32   — 지휘 트랙 먼저, 그다음 파트마다 하나
            설정 영역: 94바이트 (Ballade2 이후) / 2바이트 (가장 오래된 파일)
            지휘(conductor) 블록
            파트 블록 × 파트 수     — 각각 크기표 값보다 81바이트 큼
```

✅ 파일이 곧 **프로그램 메모리(힙)의 그대로 사본**이다. 블록마다 할당기 여백과
이전에 쓰던 찌꺼기가 섞여 있어서, **"사용한 바이트 수" 필드를 보고 거기까지만
읽어야 한다.** 블록 끝까지 읽으면 편집기의 찌꺼기가 음악으로 읽힌다. 이 필드를
찾기 전에는 레코드 첫 바이트 256가지가 골고루 나오는 것처럼 보였는데, 찾고 나니
음표가 아닌 레코드 25,000개 중 24,994개가 쉼표 명령 하나였다.

> 어떤 필드가 값 200가지를 가진 것처럼 보이면 먼저 여백(찌꺼기)을 의심할 것.

### 설정 영역

✅ 크기표 끝(`S` = `0x46 + 4 × (파트 수 + 1)`) 기준 `S + 9`에 **곡 전체 조옮김**
(부호 있는 16비트)이 있다. 바로 앞은 마스터 볼륨과 기본 템포다.

## 3. 파트 블록

| 오프셋 | 크기 | 내용 |
|---|---|---|
| `+0` | 81 | 할당기 여백 (이전 내용 찌꺼기) |
| `+81` | 12 | 파트 이름 (Shift-JIS) |
| `+94` | 1 | **음원**: 0 LA, 1 PCM, 2 LA 리듬, 4 GS, 5 GS 리듬 |
| `+112` | 2 | 영역 1이 쓴 바이트 수 |
| `+114` | 2 | 영역 2가 쓴 바이트 수 |
| `+116` | 2 | 영역 3이 쓴 바이트 수 |
| `+158` | … | 영역 1, 영역 2, 영역 3 순서로 이어짐, 그 뒤 여백 |

✅ 영역 1과 2는 **같은 구간을 재는 두 개의 시계**다. 둘의 길이 합이 **항상 같다.**
파트를 제대로 읽었는지 확인하는 가장 싼 방법이다.

### 영역 1 — 음표, 8바이트

| 바이트 | 내용 | |
|---|---|---|
| 0 | 음 번호 | ✅ |
| 1 | gate (음 길이, 0이면 음 없음) | ✅ |
| 2 | step (다음 레코드까지, 1바이트) | ✅ |
| 3 | **밀기(nudge), 부호 있음** — 음만 옮기고 시계는 안 옮김 | ✅ |
| 4 | velocity | ✅ |
| 5~6 | 악보 표기용 | ✅ |
| 7 | 플래그. **비트 7 = 앞 레코드에 붙임줄로 이어짐** | ✅ |

✅ **바이트 3은 step의 상위 바이트가 아니다.** step을 16비트로 읽으면 대부분 맞다가
`26 30 30 fe`에서 `0xfe30` = 65,072틱이 된다. 한 마디가 192틱이므로 step은 1바이트다.
바이트 3을 밀기로 읽자 17곡 일치가 **70% → 93%**가 됐다.

✅ **비트 7 붙임줄**: 마디선을 넘는 한 음을 음표 머리 두 개로 적은 것이다. 둘 다
치면 음이 하나 더 생기고 뒤가 전부 밀린다.

### 영역 2 — 컨트롤러, 4바이트

```
[상태, step, 데이터1, 데이터2]
```

상태 `0x00`은 **기다리기만** 한다. `0xB0`(컨트롤 체인지), `0xC0`(프로그램),
`0xE0`(피치 벤드)은 보이는 그대로다. ✅

### 영역 3 — 6바이트

마디 목록이다. 재생에는 필요 없다.

두 영역 모두 **첫 바이트 `0xFC`가 영역의 끝**이다.

## 4. 시간

- ✅ **4분음표 = 48틱.**
- ✅ **곡은 한 마디 뒤에서 시작한다.** Ballade는 한 마디를 카운트로 세고, 모든
  스트림은 그 마디가 끝난 지점 기준으로 적혀 있다.
- ✅ **곡 전체 조옮김은 리듬 파트(음원 2, 5)에 적용하지 않는다.** 리듬 파트의 음
  번호는 드럼 슬롯이다. 파트 머리에도 비슷해 보이는 바이트가 있지만, 그것을
  파트별 조옮김으로 쓰면 일치가 0%가 된다.

### 지휘 블록

- ✅ 블록 시작 `+77`에 마디 기록(12바이트): `u16 마디 길이(틱)`, `u8 박자 분자`,
  `u8 박자 분모`.
- ✅ 템포 스트림은 힙 조각 끝 표시 `FF 7F FF FF FF FF`가 **마지막으로** 나온 곳에서
  12바이트 뒤부터 시작한다. 레코드는 `[u16 step, u16 템포값]`이다.

### 템포값은 슬라이더 위치다

✅ SNG2S에 템포값 1~127을 하나씩 넣어 보면, 2씩 오르다가 8번째마다 한 번 멈추는
곡선이 나온다.

```
BPM = 2v − ⌈v / 8⌉          61 → 114,  72 → 135,  91 → 170
```

3/4박자 곡은 같은 값에서 BPM이 1 높게 나오는데, 이것은 SNG2S의 반올림이다.
실제 드라이버는 타이머를 설정하므로 박자를 알 수 없다. 그래서 모든 박자에 같은
곡선을 쓴다.

## 5. 맞지 않는 두 곡 — 파일 문제

- `MAGICAL0.SNG`: 126 KB에서 **잘린 파일**이다. 리듬 파트가 반쯤 없다. 마지막
  블록만 파일 끝을 넘어도 허용해서 나머지 9개 파트는 연주한다.
- `3X3EYES2.SNG`: SNG2S와 맞추려면 중간에 10,029틱을 끼워 넣어야 하는데, 파일에
  그런 지시가 없다. 지휘 블록은 97마디, 모든 파트는 96마디로 서로 맞는데 SNG2S는
  148마디를 만든다. 추측으로 맞추지 않고 그대로 두었다.

## 6. 미확인

- ❓ 설정 영역 94바이트 중 조옮김·마스터 볼륨·기본 템포 외의 필드.
- ❓ 영역 1의 바이트 5~6(악보 표기)의 정확한 뜻.
- ❓ 음원 3번 등 표에 없는 음원 값.
