옥소리 노래방 NORE45의 곡 파일이다. 세 확장자가 **같은 컨테이너**를 쓴다. 안에는
**XOR로 가린 표준 MIDI 파일(SMF)**과 가사, 악기가 들어 있다.

| 확장자 | 연주 방식 |
|---|---|
| `.OKA` | SMF를 **OPL FM 음원으로** 연주. 곡에 들어 있는 악기 사용 |
| `.OKM` | SMF를 MIDI 음원으로 연주 |
| `.OKW` | `.OKM`과 같고, 파일 끝에 녹음(음성) 데이터가 붙음 |

## 1. 컨테이너

✅ 아래 구조로 기준 파일 86개를 **다시 만들었을 때 86개 모두 원본과 바이트까지
같았다.** 크기 필드, 악기 개수, 평문 사본까지 계산해서 만들었으므로 구조를
흉내 낸 것이 아니라 이해한 것이다.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| `0x000` | 17 | `"Oksori Music File"` (평문 시그니처) |
| `0x01A` | 3 | `1A 0A 10` |
| `0x027` | … | 제목과 가사 미리보기 (평문, 조합형 한글). 제목은 `0x27`, 미리보기는 `0x85` |
| `0x15A` | 1 | **멜로디(노래) 채널** (0부터 셈) |
| `0x1AE` | 4 | 가사 싱크 블록 크기 |
| `0x1B2` | 2 | 가사 텍스트 블록 크기 |
| `0x1B4` | 2 | 예비 블록 크기 |
| `0x1CA` | 2 | 본문 전체 크기 (아래 다섯 블록 합) |
| `0x1CE` | 4 | **MIDI 크기** |
| `0x1D2` | 2 | 악기 블록 크기 |
| `0x1F2` | 1 | `0x01` |
| `0x1F6` | 2 | 녹음 샘플레이트 (`.OKW`만) |
| `0x1F8` | 1 | 악기 레코드 개수 |
| `0x210` | 256 | **복호화한 SMF의 앞 256바이트 평문 사본** |
| `0x310` | … | **본문. 전부 XOR `0xA8`** |

본문은 다음 순서로 이어진다. 모두 바이트마다 `0xA8`과 XOR되어 있다.

```
0x310   MIDI (SMF)          크기 = [0x1CE]
        가사 싱크 블록       크기 = [0x1AE]
        가사 텍스트 블록     크기 = [0x1B2]
        예비 블록            크기 = [0x1B4]
        악기 레코드          크기 = [0x1D2]   (38바이트 × 개수)
(그 뒤) .OKW 녹음 데이터 — XOR 안 됨
```

`0xA8`로 XOR하면 `MThd`로 시작하는 평범한 SMF가 된다.

## 2. 가사

✅ **텍스트 블록**: 조합형 한글, 줄마다 `CR LF`로 나뉜다.

✅ **싱크 블록**: 5바이트 레코드의 나열이다.

```
u16  틱 (SMF 틱)
u16  텍스트 블록 안의 바이트 위치 — 이 틱에 하이라이트할 글자
u8   ❓
```

글자마다 정확한 시점이 표로 들어 있어서 `.OKM` 가사 싱크는 추측이 필요 없다.
(`.NOB`는 이런 표가 없고 대신 가사 블록의 모양이 시간을 나타낸다 — [nob.md](nob.md).)

## 3. `.OKA`를 OPL로 연주하는 규칙

NORE45는 가요방과 **같은 OPL 드라이버**를 쓴다. `FUN_19aa_1162`는 GAYOBANG의
`FUN_255a_1222`와 함수 단위로 같다(리듬 비트, 레지스터 8 = `0x40`, 채널 8에 음 24,
채널 7에 음 31, 11채널). 그래서 [gyb.md](gyb.md) 5절의 규칙이 모두 그대로
적용되고, 아래는 SMF를 OPL로 옮길 때의 규칙이다.

| SMF 이벤트 | 해석 | |
|---|---|---|
| 채널 0~10 | OPL 채널 0~10에 1:1. 리듬 모드 배치는 GYB와 같음 (6 베이스 드럼 ~ 10 하이햇) | ✅ |
| 채널 11 이상 | 무시 | ✅ |
| 음 켜기 | **벨로시티가 곧 채널 볼륨.** CC7과 곱하지 않는다 | 📏 |
| 음 끄기 | 거의 없음 (라이브러리 음 켜기 119,984개 중 음 끄기 901개, 0.75%). 다음 음이 올 때까지 계속 울린다 | ✅ |
| 프로그램 체인지 | GM 번호가 아니라 **곡 안 악기 레코드의 슬롯 번호.** 악기만 바꾸고 울리던 음은 다시 치지 않음 (`FUN_1bd4_0142`) | ✅ |
| CC7 | 벨로시티와 같은 채널 볼륨으로 바로 적용 | 📏 |
| 피치 벤드 | NORE45가 **2.5배로 넓힌 뒤** 넘긴다 (아래) | ✅ |

✅ **피치 벤드 확장** (`FUN_1bd4_0105`):

```
넘기는 값 = ((벤드 − 0x2000) × 5 + 0x3FFC) / 2
```

원본 코드에서는 16비트 연산 때문에 `0xE000`과 OR하는 모양으로 보인다. 날 값을
그대로 쓰면 모든 벤드가 2.5배 얕아진다. `.GYB`→`.OKA` 변환기가 벤드를 한 칸 300으로
적었고, 이것을 2.5배 해야 750이 되어 `.GYB`(한 칸 819)와 비슷해진다.

✅ **채널 10은 가사 마커가 아니라 하이햇이다.** `SOVIRGIN.OKA`의 채널 10에는 음
42/46(닫힌·열린 하이햇) 음 켜기가 1,488개, `CLHIHAT0`/`OPHIHAT` 슬롯을 오가는
프로그램 체인지가 890개 있다.

✅ **악기 변경 때 다시 치지 않는 것이 GYB보다 더 중요하다.** 음 끄기가 거의 없어서
프로그램 체인지 4,018개 중 3,282개(82%)가 소리 나는 중에 온다. 다시 치면
63곡 중 60곡에서 잘못된 타격음이 생긴다.

악기 레코드 구조와 빈 레코드 처리는 [opl-instrument.md](opl-instrument.md) 참고.
`.OKA`는 GYB와 반대로 **NORE.BNK를 먼저, GAYO.BNK를 다음에** 본다.

📏 `.OKA` 슬롯 1,638개 중 1,092개(67%)가 빈 레코드다. 그래서 두 뱅크 파일
(`GAYO.BNK`, `NORE.BNK`)이 없으면 `.OKA`의 3분의 2가 소리를 내지 못한다.

## 4. 알려진 차이와 미확인

- `.GYB`와 같은 곡을 `.OKA`로 변환한 파일은 **쉼표가 모두 빠져 있다**
  ([gyb.md](gyb.md) 9절). 재생기 문제가 아니다.
- ❓ 싱크 레코드의 5번째 바이트.
- ❓ 예비 블록(`[0x1B4]` 크기)의 용도.
- ❓ `.OKW` 녹음 데이터의 형식 (샘플레이트 필드만 확인).
