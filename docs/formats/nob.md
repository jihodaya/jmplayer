# `.NOB` — 옥소리 노래방 (4.0 이전)

> 표시: ✅ 확인됨 · 📏 실측으로 맞춤 · ❓ 미확인 ([README](README.md) 참고) · [English](en/nob.md)

옥소리 노래방 4.0 이전 버전의 곡 파일이다. 짧은 머리 뒤에 **평문 표준 MIDI
파일**이 있고, 그 뒤에 가사가 붙어 있다.

## 1. 구조

```
0x00  u8    플래그 (0x08)
0x01  15    곡 제목 (완성형 EUC-KR — 가사는 조합형이라 서로 다름)
0x10  ...   설정 데이터 ❓
0x45        표준 MIDI 파일 (Format 1, "MThd")
            ... FF 2F 00  (마지막 트랙의 끝)
            NUL 여백 (보통 100바이트 넘음)
            가사 블록 (파일 끝까지)
```

✅ 머리는 69바이트(`0x45`)로 고정이다. `0x45`에서 `MThd`가 보이면 `.NOB`다.

곡 폴더의 `NOB.LST`에 제목 목록이 따로 있는 경우도 있다.

## 2. 가사 블록 — 모양 자체가 시간표

`.OKM`은 글자마다 틱을 적은 표를 따로 갖지만([oka-okm-okw.md](oka-okm-okw.md)),
`.NOB`에는 그런 표가 없다. 대신 **가사 블록이 피아노 롤처럼 생겼다.**

- 글자는 **노래하는 시점에 해당하는 칸**에 놓여 있다.
- 글자 사이의 공백과 짧은 NUL 묶음이 **기다리는 시간**이다.
- 앞쪽의 긴 NUL 여백이 **전주**다.
- NUL이 5개 이상 이어지면 줄 바꿈이다.
- 한글(조합형)은 한 글자가 2바이트, 즉 두 칸을 차지한다.

📏 **칸과 틱의 관계** (라이브러리 실측, 2026-07-31):

```
틱 = 칸 위치 × 20.44
```

- 칸 위치는 `FF 2F 00` 바로 다음 바이트를 0으로 센다. **NUL 여백도 센다** —
  그것이 전주 시간이다.
- 원점을 지나는 직선으로 맞춰도 R² = 0.9990이다(88%의 파일이 0.98 이상).
  즉 **칸 0이 곧 곡의 틱 0**이다.
- 노래 채널 음표 수와 가사 글자 수가 1:1로 맞는 574곡에서 맞춘 중앙값이
  **칸당 20.44틱**이다.
- 이 값은 **MIDI 해상도와 상관이 없다.** TPQN 120 곡은 20.50, TPQN 192 곡은
  20.44가 나왔다. 가사 롤이 하나의 고정 해상도로 만들어졌다는 뜻이고, 그래서
  DOS 재생기는 템포 맵을 몰라도 가사를 흘릴 수 있었다.

> 헤더 `0x28`이 해상도 필드처럼 보였던 적이 있다(상관계수 0.66). 하지만 같은
> 값을 가진 파일끼리 다른 배율이 필요했고, 다른 값을 가진 파일이 같은 배율을
> 필요로 했다. 이 값을 썼더니 `0125`, `0127` 두 곡이 10초씩 어긋났다. 표본이
> 만든 착시였다.

## 3. 미확인

- ❓ `0x10`~`0x44` 설정 데이터의 뜻.
- ❓ 칸당 20.44틱이 원본 프로그램의 어떤 상수에서 나오는지. 원본 실행 파일을
  디컴파일하지 않고 실측만으로 정한 값이다.
